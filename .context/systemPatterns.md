# Архитектурные решения — book-translate

### Текст читается глазами, OCR — только геометрия

- **Контекст.** Сканы без текстового слоя; tesseract по сжатому скану путает буквы.
- **Выбор.** Перевод — по картинке страницы в JSON; tesseract только находит, где
  стоит блок и какие в нём слова, чтобы сопоставить блок с подписью по триграммам.
- **Альтернативы.** Перевод OCR-текста — отвергнут: ошибки распознавания уходят в перевод.

### Вёрстка подгоняется в Chrome, а не в PIL

- **Выбор.** HTML поверх скана, кегль и рост плашек подбирает JS в headless
  Chrome, PDF — `--print-to-pdf`; проверка читает тот же DOM.
- **Альтернативы.** Рисовать текст в PIL — нет переносов и подгонки кегля.

### Ошибки чинятся классом

- **Выбор.** Каждое замечание по странице превращается в правило для всех таких
  страниц (выкройки, наклонные подписи, сноски, цитаты) и число в `check`.
- **Альтернативы.** Ручные правки страниц — ломаются при пересборке.

### Конфиг книги одним yaml

- **Выбор.** `book.yaml` с плоскими полями, проверкой неизвестных имён и типов;
  язык книги обязателен.
- **Альтернативы.** Группы hydra — у пайплайна нет вариантов моделей и прогонов.

### Текст перевода — недоверенные данные

- **Контекст.** Перевод и OCR попадают в HTML, который исполняет Chrome.
- **Выбор.** Экранирование на каждой вставке (и в JS подгонки), CSP с хешем
  единственного скрипта, Chrome с песочницей и новым профилем на каждый запуск,
  сборочные файлы в каталоге книги, атомарная запись, PDF не перезаписывается
  без `--force`, идентификаторы страниц и slug проверяются.
- **Граница.** Конфиг книги — доверенный: он называет запускаемые программы и
  пути вывода, титул — HTML.
